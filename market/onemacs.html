왜 CLI인가

챗봇은 밖에 있는 상담원.
CLI는 내 컴퓨터 안에 들어와 앉은 직원.

같은 AI라도 어디에 앉혀 놓고 쓰느냐가 다릅니다. 챗봇 사이트는 AI가 회사 창구에 있어서, 내가 서류를 들고 가서 보여주고 답을 받아 적어 와야 합니다. CLI(터미널)는 AI가 내 컴퓨터 안 내 방에 앉아서 내 서랍을 직접 열고 일합니다.

1. 심부름이 사라진다

챗봇은 파일을 올리고, 답을 복사하고, 내려받아 제자리에 넣는 일이 전부 내 몫입니다. CLI는 내 폴더 안에서 읽고, 고치고, 그 자리에 저장합니다. 저장이 곧 완료. 보고서 100장을 고치라고 하면 100장이 고쳐진 채로 그 폴더에 있습니다.

2. 손이 있다

챗봇은 "이렇게 하세요"라고 말만 합니다. CLI는 직접 합니다. 프로그램을 설치하고, 돌려 보고, 안 되면 고치고, 다시 돌려 봅니다. 내 컴퓨터에 깔린 도구는 전부 씁니다. 엑셀 정리, 사진 일괄 변환, 웹사이트 만들기, 주식 데이터 내려받기 — 말로 시키면 손으로 합니다.

3. 결과물이 바로 옆에 있다

웹사이트를 만들라고 하면 파일이 내 폴더에 생기고, PC에서는 그 자리에서 열립니다. 폰에서는 콘솔 위쪽 버튼 하나로 그 사이트를 콘솔 안에서 바로 열어 눌러봅니다. 스캐너 "262종목" 버튼이 그 예입니다. 만들고 → 눌러보고 → "여기 고쳐" → 다시 눌러보고. 이 순환이 폰 한 화면에서 끝납니다. 버튼을 새로 다는 것도 말로 합니다.

방금 만든 랜딩페이지, 위쪽에 버튼으로 달아줘
"랜딩" 버튼을 달았습니다. 누르면 콘솔 안에서 바로 열립니다.

4. 몸이 가볍다

데스크톱 앱은 예쁜 화면을 그리려고 브라우저 한 벌을 통째로 안고 뜹니다. 그래서 무겁습니다. CLI는 글자만 주고받으니 그릴 게 없습니다. 켜는 데 0.1초, 앉아만 있을 땐 메모리 70MB 남짓. 그래서 한 컴퓨터에 AI 직원 수십 명을 앉혀 놔도 컴퓨터가 안 버벅입니다. 오래된 노트북, 켜 둔 채 두는 PC에서 차이가 납니다.

데스크톱 앱이 무거운 이유는 만드는 회사 문서에 그대로 적혀 있습니다: "웹브라우저와 구조가 거의 같다", "앱 창 하나마다 화면 그리는 프로세스가 따로 뜬다". 반대로 CLI는 화면 그리는 부분이 아예 없습니다.

5. 한 번 시킨 일을 저절로 돌게 할 수 있다

챗봇은 매번 내가 들어가서 말을 걸어야 합니다. CLI는 한 줄로 부를 수 있어서 "매일 아침 9시에 이거 해", "이 파일이 바뀌면 저거 해"처럼 걸어 두면 사람이 없어도 돕니다. 끝나면 성공인지 실패인지 신호를 남겨서, 실패하면 다시 시키거나 알림을 보내게 할 수 있습니다.

6. 넷 다 같은 모양이라 한 상에 앉힌다

Claude·OpenAI(Codex)·Google(Antigravity)·xAI(Grok) 네 회사가 전부 이 CLI 방식을 내놓았습니다. 모양이 같으니 나란히 두고 한 서버 밑에서 함께 일하게 할 수 있습니다. 앱이나 사이트였다면 넷을 한 화면에 묶기가 어렵습니다. 이 앱이 "AI 4종"을 한 화면에 올릴 수 있는 이유가 바로 이것입니다.

왜 데몬인가

대화창을 띄워 마주 앉는 직원이 아니라,
쪽지만 주면 뒤에서 처리하고 결과만 놓고 가는 직원.

Claude Code만 대화창을 띄웁니다. Codex·Antigravity·Grok은 대화창 없이 뒤에서 자동으로 일하는 모드(헤드리스·데몬·백그라운드 프로세스 모드)로 돕니다. 데몬은 "대화창 없이 뒤에서 조용히 일하는 일꾼"이라는 뜻입니다.

1. 내 화면에 대화창이 안 뜬다

AI를 3개 더 켜도 PC 화면은 그대로입니다. 대화창 4개를 오가며 알트탭 할 일이 없습니다.

2. 물어보고 기다리지 않는다

대화창 직원은 "이거 해도 될까요?"를 묻고 내가 답할 때까지 멈춥니다. 데몬 직원은 정해진 방 안에서 끝까지 하고 결과만 놓고 갑니다. 그래서 지하철에서 시켜 놓고 도착하면 끝나 있습니다.

3. 일 없으면 자리를 비운다

쓸 때만 켜지고 끝나면 꺼집니다. 앉아서 컴퓨터 힘을 먹고 있는 시간이 0입니다.

4. 셋을 동시에 시켜도 된다

각자 따로 일하니 서로 기다리지 않습니다. Codex에는 검토, Antigravity에는 조사, Grok에는 초안 — 한 번에 던지고 한 번에 받습니다.

5. 결과가 정해진 서식으로 나온다

사람이 읽는 문장이 아니라 다음 직원이 바로 받아 쓸 수 있는 형식으로 내놓습니다. 그래서 Claude Code(메인)가 셋의 결과를 받아 종합하고, 다음 일로 넘길 수 있습니다.

6. 시킨 대로 했는지 기록이 남는다

주고받은 것이 전부 파일로 남습니다. 나중에 "그때 뭘 시켰고 뭘 했지"를 다시 열어볼 수 있습니다.

"물어보지 않는다"가 위험하지 않은 이유 — 데몬 직원은 정해진 방(프로젝트 폴더) 밖으로 못 나갑니다. 포맷·전체 삭제·컴퓨터 끄기 같은 위험한 일은 문 앞에서 막힙니다. 폰의 🛑 정지 버튼이 언제든 멈춥니다. 오래 걸리면 자동으로 정리됩니다. 그리고 전부 기록이 남습니다.

챗봇 창이 아니라 각 회사의 CLI입니다. CLI는 내 PC 파일을 직접 열어 고치고 저장하고, 명령을 실행합니다. Claude Code 공식 문서도 터미널판을 "full-featured CLI"로 부르고, 파이프·스크립트·자동 실행(-p)으로 엮이는 "composable, Unix philosophy" 도구라고 씁니다. 데스크톱 앱은 같은 엔진을 GUI로 감싼 것, 웹은 내 PC에 없는 저장소용입니다.

콘솔 서버 + 터널약 190MB · AI 3종(헤드리스·데몬·백그라운드 프로세스 모드)은 부를 때만
CLI 기동0.12초 (실측)
비교: Windows 데스크톱 앱에이전트 모드 후 매 실행 1.8GB Hyper-V VM 동반 현상 보도 (Neowin 2026-06-10, "CLI 사용자는 해당 없음")

모델 응답 속도는 같은 엔진이라 동일합니다. 차이는 껍데기가 먹는 메모리와 기동 시간이고, CLI에는 껍데기가 없습니다.

2대화창은 Claude Code 하나만 — 나머지는 헤드리스·데몬·백그라운드 프로세스 모드

Claude Code만 대화창을 띄웁니다. Codex는 codex exec, Antigravity는 agy -p, Grok도 대화창 없이 뒤에서 자동으로 일하는 모드(헤드리스·데몬·백그라운드 프로세스 모드)로 실행됩니다. AI를 3개 더 켠다고 대화창이 3개 더 생기지 않습니다. 네 AI 모두 같은 프로젝트 폴더에서 파일을 읽고 쓰고 명령을 실행합니다.

헤더 우측 "남은 5h · 7d"는 Claude·Codex 구독의 5시간/7일 잔여 한도입니다(60초 갱신).

3Claude Code를 중심으로 나머지 셋과 협업한다

Claude Code 하나에게만 말해도 됩니다. Claude Code가 중심이 되어 "이건 Codex에게 검토시켜", "셋 다 돌려서 비교해"처럼 역할을 나누고 결과를 종합합니다. 위임은 한 명씩도, 세 워커 동시도 됩니다.

반대로 직접 작업을 시키고 싶으면 탭을 눌러 4개 AI에게 각각 동시에 다른 일을 시킬 수 있습니다. 워커마다 독립 프로세스라 서로 기다리지 않습니다. Claude Code엔 구현, Codex엔 검토, Antigravity엔 조사, Grok엔 초안 — 한 번에.

방금 만든 전략 파일, Codex랑 Antigravity 둘 다에게 검토시켜서 다른 의견만 정리해줘
Codex·Antigravity에 동시 위임했습니다. (진행 중… 각 탭에서 확인 가능)
4진짜 내 PC 대화창을 움직인다 — 입력 경로 3개

폰 채팅창에 쓴 글이 PC의 Claude Code 대화창에 그대로 타이핑되고, PC 대화창의 대화가 폰에 그대로 비칩니다. 별도 세션이 아니라 평소 쓰던 그 대화창이라 내 프로젝트 폴더·설정·기록을 전부 아는 상태로 일합니다.

같은 세션에 들어가는 문이 셋입니다. ① PC 앞에서는 터미널, ② Anthropic 공식 Remote Control로 Claude 모바일 앱에서, ③ 이 콘솔. 어디서 넣든 한 Claude Code가 한 프로젝트를 이어서 일합니다.

대화는 요약 / 상세 / 전체 세 단계. 폰에서는 요약만, PC에 앉으면 전체를. Remote Control은 Anthropic 기능이며 본인 Claude 구독으로 씁니다.

5PC 여러 대 × 프로젝트 여러 개, 앱 하나

집 PC, 사무실 PC, 노트북 — 각각에 콘솔을 깔고 같은 페어링 코드를 쓰면 앱 상단에 PC 탭이 나란히 뜹니다. 허브는 "어느 PC의 어느 프로젝트가 지금 어느 주소에 켜져 있나"를 PC·프로젝트 단위로 기억하므로, 사무실 PC의 "트레이딩 시그널"과 집 PC의 "블로그"를 한 앱에서 오갑니다. 켜진 PC는 초록불, 꺼진 PC는 회색.

6프로젝트 = 폴더. 폰에서 추가, 개수 제한 없음

폴더 하나를 등록하면 새 작업대가 생깁니다. 폴더가 곧 지식베이스라 프로젝트끼리 섞이지 않고, 프로젝트마다 Claude Code가 따로 붙어서(첫 번째 프로젝트는 대화창, 그 외는 헤드리스·데몬·백그라운드 프로세스 모드) 지시가 다른 프로젝트로 새지 않습니다.

폴더가 없어도 됩니다. 콘솔 메뉴의 "＋ 프로젝트 추가"에 이름만 넣으면 PC에 그 이름의 폴더가 만들어지고, 거기서 새 Claude Code가 일을 시작합니다. 지하철에서 프로젝트를 새로 시작할 수 있습니다.

7덤: 기본 프로젝트 "트레이딩 시그널" — 코드 0줄로 전략

국내 주식 262종목 스캐너와 샘플 전략이 들어 있습니다. 지표 조합을 문장으로 말하면 Claude Code가 전략 JSON을 만들고 검증·백테스트까지 한 뒤 스캐너 전략 탭에 올립니다. 전략은 켜고 끄고, A/B/C 개수 제한 없이 저장·비교.

RSI 30 이하 + 거래량 20일 평균의 2배 + 20일선 위로 올라온 종목 잡는 전략 만들어줘. 이름은 "눌림목 반등".
전략 파일 생성 → 조건식 검증 → 과거 데이터 백테스트 → 결과 요약. 스캐너 전략 탭에 "눌림목 반등"이 추가됐습니다.
