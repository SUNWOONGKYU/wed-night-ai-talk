# WAAT.community 개편안 초안

> 버전: v0.1 초안
> 작성일: 2026-07-22
> 범위: 웹사이트의 역할, 정보 구조, 운영 방식, 단계별 구현 범위. 기존 소스코드는 변경하지 않는다.

## 1. 개편의 한 문장

WAAT.community를 **AI 수다방의 빠른 대화가 WAAT 모임 참여로 이어지고, 모임에서 나온 경험과 지식이 다시 축적되는 커뮤니티의 본체**로 만든다.

카카오 수다방은 실시간 대화를 가장 잘하는 공간으로 남긴다. 웹사이트는 대화를 옮겨 담는 게시판이 아니라, 처음 온 사람이 신뢰를 얻고 모임을 고르며, 참여자가 관계와 기록을 이어 가고, 운영자가 프로그램과 콘텐츠를 관리하는 중심 공간이 된다.

## 2. 초안의 근거와 전제

### 대화 원문에서 확인한 방향

- 약 3,000명 규모의 AI 수다방이 이미 실시간 접점으로 존재한다.
- WAAT를 중심으로 오프라인 만남이 이어진다.
- 웹사이트는 지식, 회원, 모임, 사업의 본체가 되어야 한다.
- 카카오방의 기능을 웹에 억지로 복제하지 않는다.
- 목표는 단순 게시판 개편이 아니라 수준 높고, 깔끔하며, 사용하기 편한 커뮤니티 경험이다.

`3,000명`은 대화 원문에 나온 운영 규모다. 공개 화면에서 사용하려면 실제 운영자가 최신 수치를 확인한 뒤에만 표기한다.

### 현재 소스코드에서 확인한 기반

현재 WAAT는 이미 다음 기능을 갖추고 있다.

| 현재 기능 | 개편 후 판단 |
| --- | --- |
| 메인 페이지의 모임 일정·장소·커뮤니티 미리보기 | 유지하고, 방문자가 바로 다음 행동을 고르도록 재배치 |
| 회원가입·로그인·내 프로필 | 유지하고, 참여 이력과 관심 설정의 기반으로 확장 |
| 모임별 신청·회차·정원 관리 | 유지하고, WAAT 회차 운영과 향후 특별 프로그램 확장의 기반으로 정리 |
| 자유발언 게시판·댓글·이미지·외부 원문 링크 | 유지하고, 모임 기록과 지식 축적에 맞게 분류 정리 |
| 관리자 멤버·모임·장소·문의·이메일 관리 | 유지하고, 큐레이션과 프로그램 운영 도구를 보강 |

따라서 1차 개편에서 프론트엔드나 Supabase를 전면 교체할 이유는 없다. 정보 구조와 운영 흐름을 먼저 고치고, 필요한 데이터 항목만 점진적으로 늘린다.

## 3. 해결할 문제

현재 구조는 개별 기능은 작동하지만, 방문자가 "이곳은 어떤 커뮤니티이고 지금 무엇을 하면 되는가"를 한 흐름으로 이해하기 어렵다. 특히 다음 연결이 약하다.

1. 수다방에서 관심이 생긴 사람과 첫 모임 신청 사이의 연결
2. WAAT 모임의 성격과 회차를 이해하고 선택하는 연결
3. 모임에서 나눈 대화와 이후 게시글·자료·다음 참여 사이의 연결
4. 운영자가 좋은 대화와 성과를 선별해 커뮤니티 자산으로 남기는 연결

개편의 핵심은 메뉴를 늘리는 일이 아니라, 이 네 연결을 끊기지 않게 만드는 일이다.

## 4. 서비스 역할 분리

| 공간 | 맡는 역할 | 하지 않을 일 |
| --- | --- | --- |
| AI 수다방 | 빠른 질문, 가벼운 공유, 당일 공지, 자연스러운 대화 | 모든 대화를 영구 기록으로 보관 |
| WAAT.community | 프로그램 안내·신청, 회원 경험, 선별된 기록, 지식 아카이브, 공식 공지·협력 창구 | 카카오방을 복제한 실시간 채팅방 |
| 오프라인 모임 | 관계 형성, 깊은 토론, 함께 만들기, 다음 행동 만들기 | 참석자만 아는 내용을 방치 |

수다방의 내용을 웹으로 옮길 때는 운영자가 요약한 **대화 스냅샷**만 발행한다. 원문 대화, 개인 발언, 사진은 동의 없이 자동 수집·공개하지 않는다.

## 5. 새 정보 구조

공개 메뉴는 다섯 개면 충분하다.

| 메뉴 | 역할 | 핵심 행동 |
| --- | --- | --- |
| 홈 | WAAT의 정체성과 이번 주의 선택지를 한 화면에 제시 | 이번 모임 보기, 참여 신청 |
| 프로그램 | WAAT 모임과 향후 특별 프로그램의 일정·상세 | 일정 확인, 참여 신청 |
| 커뮤니티 | 질문·성과·협업·토론이 이어지는 현재형 공간 | 읽기, 글쓰기, 댓글 달기 |
| 아카이브 | 모임 후기, 대화 스냅샷, 유용한 자료, 프로젝트 결과를 다시 찾는 공간 | 주제 탐색, 다음 모임으로 이동 |
| WAAT 소개·협력 | 운영 원칙, 처음 온 사람 안내, 파트너십·제안 문의 | 가입, 협력 문의 |

로그인 뒤에는 공개 메뉴와 별도로 **내 WAAT**를 제공한다. 여기에는 내 신청 내역, 관심 주제, 내가 쓴 글, 알림 설정만 둔다. 초기에는 공개 회원 명부를 만들지 않는다. 관계 추천은 개인정보와 운영 기준이 충분히 정리된 뒤에 검토한다.

### 홈 화면의 우선순위

첫 화면은 장식보다 선택을 먼저 보여준다.

1. WAAT가 어떤 모임인지와 이번 주의 가장 가까운 참여 기회
2. 이번 WAAT 모임의 주제와 참여 방식을 한눈에 이해하는 안내
3. 최신 일정과 명확한 신청 버튼
4. 운영자가 고른 커뮤니티 대화·만든 것·모임 기록
5. 지난 기록을 보고 다음 모임으로 이어지는 아카이브 입구
6. 운영 철학과 협력 문의

기존 풍선과 대화의 브랜드 감정은 살리되, 첫 화면의 주인공은 장식이 아니라 `다음 모임`과 `WAAT가 주는 경험`이어야 한다.

## 6. 핵심 사용자 흐름

### 처음 온 사람

AI 수다방 또는 외부 링크 → 홈 → WAAT 모임의 주제와 참여 방식 확인 → 일정 상세 → 가입 또는 간편 로그인 → 회차 신청 → 신청 확인과 준비 안내

가입 전에는 일정·소개·아카이브를 충분히 볼 수 있게 한다. 신청 또는 글쓰기 시점에만 가입을 요구해 진입 장벽을 낮춘다.

### 반복 참여자

홈 또는 알림 → 내 관심 주제의 다음 모임 확인 → 신청 → 모임 참여 → 후기·질문·만든 것 게시 → 다음 회차 또는 관련 아카이브 탐색

### 운영자

프로그램 등록 → 회차·정원·장소·안내 관리 → 신청자 확인·공지 발송 → 모임 후 핵심 기록 선별 → 아카이브 발행 → 다음 모임의 주제와 안내에 반영

## 7. 화면과 콘텐츠 설계

### 프로그램

프로그램 페이지는 일정 목록이 아니라 "어떤 경험에 참여할지" 고르는 화면이다.

- 상단에서 이번 WAAT 모임의 주제·일정과 향후 특별 프로그램을 구분한다.
- 각 프로그램에는 대상, 분위기, 주제, 진행 방식, 예상 결과를 짧게 설명한다.
- 회차 상세에는 날짜·시간·장소·정원·신청 상태·준비 사항·운영자 안내를 명확히 둔다.
- 정원이 있는 회차는 신청 가능, 마감, 대기 상태를 분명히 보여 준다.
- 신청 후에는 개인 프로필의 내 신청 내역과 연결한다.



### 커뮤니티

현재 게시판의 `AI 새 소식·공부하기·자랑하기·협력하기·질문하기·요청하기·토론하기`는 좋은 출발점이다. 다만 사용자가 분류를 오래 고민하지 않도록 다음 다섯 흐름으로 정리한다.

| 새 분류 | 기존 분류의 연결 | 쓰임 |
| --- | --- | --- |
| AI 흐름 | AI 새 소식 | 새 도구, 변화, 읽을거리 |
| 배우고 묻기 | 공부하기, 질문하기 | 사용법, 문제 해결, 학습 기록 |
| 만든 것 | 자랑하기 | 결과물, 실험, 사례 |
| 함께하기 | 협력하기, 요청하기 | 프로젝트, 도움 요청, 제안 |
| 생각 나누기 | 토론하기 | 관점, 쟁점, 깊은 대화 |

모임 후에는 `모임 기록` 태그를 별도로 붙여 해당 회차와 연결한다. 기존 글의 분류는 그대로 보존하고, 새 글부터 새 기준을 적용해 데이터 이전 부담을 줄인다.

### 아카이브

아카이브는 새 글을 모두 복제하는 공간이 아니다. 운영자가 선별한 내용을 다음 네 형식으로 묶는다.

- 모임 기록: 한 회차의 핵심 질문, 나눈 것, 다음 행동
- 대화 스냅샷: 수다방이나 커뮤니티에서 공통으로 나온 주제를 익명·요약 형태로 정리
- 실전 자료: 도구 사용법, 프롬프트, 참고 링크, 시행착오
- 만든 결과: 참가자의 프로젝트·콘텐츠·협업 사례

각 아카이브 글의 끝에는 관련 게시글, 다음 모임, 참여 신청 중 하나를 연결한다. 읽고 끝나는 콘텐츠를 다음 행동으로 바꾸기 위한 장치다.

### 내 WAAT

- 내 신청·취소·대기 상태
- 관심 주제와 선호 프로그램
- 내가 쓴 글과 댓글
- 공지·이메일 수신 설정

공개 프로필이나 회원 검색은 이 단계에서 넣지 않는다. 회원 정보는 운영과 본인 확인에 필요한 최소 범위만 사용한다.

### 운영자 화면

현재의 멤버·모임·장소·문의·이메일 관리는 유지한다. 여기에 다음을 추가한다.

- 프로그램 유형과 회차 템플릿 관리
- 모임 종료 뒤 기록 초안 생성과 공개 상태 관리
- 커뮤니티 글의 추천·아카이브 연결·숨김 관리
- 공지 대상 선택과 발송 이력 확인

## 8. 운영 원칙

1. 대화의 속도는 수다방에, 기록의 책임은 웹사이트에 둔다.
2. 모임 기록은 참석자의 발언 전문이 아니라 운영자가 정리한 배움과 다음 행동을 남긴다.
3. 운영자가 고르는 추천·아카이브는 출처와 작성자를 존중하고, 필요하면 사전 동의를 받는다.
4. 가입은 최소 정보로 시작하고, 관심사와 알림 설정은 참여가 쌓일 때 선택적으로 받는다.
5. 프로그램 수·게시글 수보다 재방문, 실제 참석, 다음 행동을 더 중요한 성과로 본다.

## 9. 데이터와 기술 방향

현재의 HTML/CSS/JavaScript, Supabase Auth·Postgres, Vercel 구조는 유지한다. 1차는 전면 재구축이 아니라 현재 테이블과 화면을 확장하는 방식으로 진행한다.

| 영역 | 우선 검토할 항목 | 원칙 |
| --- | --- | --- |
| 일정 | `program_type`, 주제, 진행자, 준비 안내, 대기 상태 | 기존 이벤트·회차·정원 구조를 우선 활용 |
| 게시글 | 새 분류, `모임 기록` 태그, 추천 여부, 연결된 회차 | 기존 게시글·댓글·이미지·외부 링크를 보존 |
| 아카이브 | 추천 게시글을 먼저 활용하고, 필요할 때만 별도 콘텐츠 테이블 추가 | 처음부터 이중 저장 구조를 만들지 않음 |
| 회원 | 관심 주제, 선호 프로그램, 수신 설정 | 공개 명부와 자동 매칭은 보류 |
| 측정 | 유입 출처, 일정 상세 조회, 신청 완료, 재방문 | 개인정보를 과도하게 수집하지 않음 |

수다방을 연동하더라도 자동 메시지 수집이나 무단 공개는 범위에서 제외한다. 필요한 경우에는 링크 공유, 운영자 수동 요약, 참여자 동의 방식만 사용한다.

## 10. 디자인 방향

- **친근하지만 가볍지 않게:** AI를 좋아하는 사람들이 편하게 말을 꺼낼 수 있으면서도, 실제 모임과 협업을 믿고 선택할 수 있어야 한다.
- **정보가 먼저:** 헤드라인, 일정, 신청 상태, 다음 행동을 모바일 첫 화면에서도 빠르게 읽을 수 있게 한다.
- **모임 중심:** 사진과 기록은 장식이 아니라 실제 사람·주제·결과를 보여 주는 증거로 쓴다.
- **일관된 언어:** `참여 신청`, `모임 기록`, `함께하기`처럼 행동의 의미가 분명한 표현을 쓴다.
- **접근성:** 작은 화면, 긴 한글 제목, 키보드 탐색, 명도 대비를 처음부터 고려한다.

## 11. 단계별 실행안

### 1단계: 진입과 프로그램 경험 정리

- 홈과 메뉴를 새 정보 구조에 맞게 재배치
- WAAT 모임의 주제·일정·회차 상세 정리
- 일정 신청과 내 신청 내역의 흐름을 명확히 연결
- 기존 모임·장소·회원·신청 기능은 그대로 유지

**완료 기준:** 처음 온 사람이 프로그램 차이를 이해하고, 한 회차를 골라 신청까지 갈 수 있다.

### 2단계: 커뮤니티를 기록과 지식으로 연결

- 새 게시 분류와 `모임 기록` 태그 도입
- 운영자 추천 글과 대화 스냅샷 발행 흐름 도입
- 아카이브 첫 화면과 관련 모임·게시글 연결

**완료 기준:** 모임이 끝난 뒤 그 경험을 다시 찾을 수 있고, 읽은 콘텐츠에서 다음 참여로 이동할 수 있다.

### 3단계: 반복 참여와 운영 효율 강화

- 내 WAAT의 관심 주제·알림·활동 이력 보강
- 관리자용 프로그램 템플릿·기록 발행·콘텐츠 큐레이션 도구 보강
- 유입부터 신청·참석·재방문까지의 측정 체계 구축

**완료 기준:** 운영자가 프로그램과 기록을 반복해서 관리하는 시간이 줄고, 참여자의 재방문 흐름을 확인할 수 있다.

## 12. 성공 지표

정확한 목표 수치는 현재 기준선을 수집한 뒤 정한다. 초기에 볼 지표는 다음과 같다.

- 수다방·외부 링크에서 온 방문자의 프로그램 상세 조회율
- 프로그램 상세 조회 후 신청 완료율
- 신청자 대비 실제 참석률과 재신청률
- 모임 기록·아카이브에서 관련 모임으로 이동한 비율
- 가입 후 30일 안에 글쓰기·댓글·모임 신청 중 하나를 한 비율
- 운영자의 공지·기록 발행에 드는 작업량과 오류 건수

## 13. 이번 초안에서 먼저 확정할 한 가지

**WAAT 정기 모임의 주기와 참여 경험을 명확히 정의하는 일**을 먼저 확정한다.

이 결정이 정해져야 홈의 첫 화면, 일정 안내 문구, 신청 흐름을 일관되게 설계할 수 있다.

## 14. 이번 초안의 범위 밖

- 카카오 수다방을 대체하는 실시간 채팅 개발
- 카카오 대화의 자동 수집·공개·학습
- 회원 공개 명부와 자동 인맥 추천
- 현재 기술 스택의 전면 교체
- 기존 게시글·신청 데이터의 일괄 재작성

이 범위를 지켜야 개편의 첫 결과를 빠르게 검증하면서도, 기존 회원 데이터와 운영 흐름을 흔들지 않을 수 있다.
